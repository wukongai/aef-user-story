# 内核与经营验证的接口评审
以下是合成预期，未运行真实对话。Definition与Business Model拥有内核及经营模型，User Story只承接现有结论。父能力不可用时说明缺口，不代做完整分析。

## CORE-01｜内核改变影响范围
父级场景：训练营内核尚未成立，拟删除辅导。
本包断言：保留已有需求与假设；检查辅导变化影响哪些MVP能力，列差异待用户决定；完整内核提炼交Definition，不要求先完成整套定义。

## CORE-02｜经营参数未定
父级场景：学员、班期、老师可能是经营计算单元。
本包断言：复用Business Model已有来源；未定参数标未知，仅说明其对当前闭环的影响，不自行选择主计算单元或编造数字。

## CORE-03｜局部MVP与反证
已有Q-07辅导必要性、Q-09交付工时，本轮只验证Q-07；发现无辅导无法完成。
本包断言：引用Q-07及版本，记录观察/反证/局限，Q-09保持未测；结果回原内核章节，并报告经营模型可能受影响；范围修改需用户确认。没有定义时回原假设记录。

## CORE-04｜请求双版商业画布
父级场景：内部工具不收费，用户要求双版画布。
本包断言：交Business Model及宿主处理，传递现有投入收益资料；不在User Story重建画布或强制章节数。仅在用户另有故事/MVP请求时承接相关结论。
