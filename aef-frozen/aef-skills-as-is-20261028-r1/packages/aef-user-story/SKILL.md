# AEF User Story

## 目标

帮助用户把产品想法转成有用户价值、可讨论和可验收的用户故事，并明确MVP要先完成的业务闭环。
从“谁要达成什么结果、为什么需要”开始，梳理Epic与故事，再细化选中的内容。可以独立使用，也可以接着Product的产品定义继续。

## 输入

一句想法、产品定义、原始需求、可读附件或已有故事都可以作为起点。先利用用户已给的背景；用户、目标或限制不清且会改变故事时，只问当前关键问题。
新项目直接从产品目标开始；有产品定义时复用有效结论；指定某条故事时直接处理该故事；用户要求继续上次任务时才接续已有决定和未决项。
区分已知事实、候选假设与未知信息。附件未读到就说明缺口，敏感内容用脱敏摘要；技术想法作为约束或后续方案，不当成用户价值。

## 流程

### 1. 理解用户与产品目标
说明服务谁、要解决什么问题、用户希望得到什么结果，以及已知限制。复杂产品先理清组成、角色职责、业务对象关系与整体流程。
整体产品请求读取[产品系统到故事](references/product-system.md)，信息足够就给可讨论的全貌；局部请求直接进入对应故事，不补做整套分析。

### 2. 梳理Epic与用户故事
按完整业务能力归类Epic，按一个用户可获得的结果拆出Story。写法见[用户故事方法](references/how-to-write-user-story.md)。
故事用“作为……，我希望……，从而……”表达。先形成可读的粗故事集合，保留用户提出的候选，不按前端、后端、数据库拆分。

### 3. 讨论MVP范围
用户需要首版范围时，讨论为验证哪项价值先完成哪个闭环，说明选中、暂缓、理由与依赖。使用[MVP范围模板](templates/mvp-scope.md)，复用已有产品内核、单元模型或验证假设；没有这些资料也可以形成诚实的范围候选。
MVP引用故事，不另写一套需求正文。由用户确认范围；只修改故事时跳过此步，已有决定不重复询问。

### 4. 细化选中故事与验收条件
与用户讨论、拆分和修改选中的故事；对准备细化的Story检查INVEST，不计算 Story Points。粗Epic和暂缓项不要求全部展开。
确认故事后，再把可观察的正常、失败和边界结果写成编号验收条件；故事确认与验收确认分别处理。仅在操作具体Story/AC对象的内容、修订或确认记录时读取[修改与确认](references/story-editing.md)。

### 5. 核对本轮交付
先核对结果粒度与系统承诺到故事的对应关系；整体复杂、跨角色/阶段或风险较高时，按[交付评审](references/story-delivery-review.md)选择相互隔离的多个AI视角，汇总后修订。视角与复核次数按事实决定；简单局部修改只复核直接影响，格式/错别字/链接自检即可。

## 输出

按用户需要交付整体初稿或指定故事：
- 整体初稿：必要的产品全貌、按Epic归类的故事集合、MVP范围候选及关键未决项。
- 选中故事：编号、标题、一句用户故事、直接按1、2、3列出的验收条件；必要业务约束简短补充。
- 局部修改：目标故事或验收的差异，以及直接受影响的内容。

故事卡的可读形式如下（验收内容在故事确认后细化）：

```markdown
### US-001 预约工具
作为居民，我希望预约可借工具，从而安排自己的使用时间。

验收条件：
1. 可以对可借工具提交预约。
2. 预约成功后可以查看领取安排。
3. 工具不可借时说明原因，不生成成功预约。
```

对话初稿即可供审阅；保存时采用一条故事一张卡、按Epic归类的总索引。仅在需要落盘或维护已有文件时加载保存规则。

## 收口与下一步

当前粒度的故事或范围已经可审阅，就提交结果，说明真正影响决策的未决项；不为填满所有细节延长访谈。草稿、内容确认、范围确认、保存和开发批准分别判断。
只做故事或MVP时，在对应交付处结束。用户要求地图或Sprint时，按[下游交接](references/downstream-handoff.md)传递固定故事引用及已有决定，由可用Product模块承接；独立环境缺少模块时提供交接摘要并说明未执行。
产品详细设计、PRD、工程Spec/Plan/Task、技术设计和编码属于后续能力，本Skill不生成这些产物，也不自动启动开发或发布。

## 按需读取的支持规则

| 实际场景 | 读取资源 |
|---|---|
| 仅调整对话中的粗故事集合或MVP选中/暂缓范围，未操作具体Story/AC记录 | 沿用当前业务方法与对话稿；无需读取操作规则、故事库或保存规则 |
| 新增、修改、拆分、合并具体Story/AC对象，或登记其确认 | [修改与确认](references/story-editing.md)；新增编号、跨包、拆分合并、退役，或本页无法回答所需修订语义时，按动作读取[共享修订规则](references/revision-core.md)；普通单条修改不因历史版本而补读 |
| 用户要求保存、校验、管理编号版本或生成下游引用 | [操作规则](references/story-operations.md)，再按实际数据格式使用其中的方法与工具 |
| 项目已有旧格式文件，或用户明确要求迁移 | [旧格式兼容](references/legacy-compatibility.md)；先识别现有格式，保持原能力 |
| 用户反馈跑偏、提出旁支、明确停止/换任务或恢复任务 | [任务边界与纠偏](references/task-focus.md)及[本能力交付与收口](references/task-focus-adapter.md) |
| 接入项目生命周期 | [集成边界](references/aef-integration.md) |

这些资源按实际动作读取；新项目讨论故事与MVP时，先完成上面的业务流程。
