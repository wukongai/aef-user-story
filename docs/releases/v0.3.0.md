# aef-user-story v0.3.0

发布日期：2026-10-13。

本版在 0.2.0 基础上增加持续维护能力：用户可在产品开发过程中随时新增故事，或只修改某条故事及验收条件，并保留稳定编号、内容修订与确认历史。

## 使用节奏
随时新增或完善故事 → 迭代规划选择故事 → 细化并确认选中故事与验收 → 对应的产品详细设计。
本 Skill 负责故事与验收维护；不自动安排迭代、不制作地图、产品详细设计或技术设计。
已有产品定义与需求会被复用，不要求每次重新梳理全部产品。

## 新增
- 独立调用、局部修改与中途恢复。
- Epic、Story、Acceptance 独立编号与修订历史。
- 过期更新检查、历史回读、逐对象确认记录。
- 故事变更后，原验收保留旧修订绑定并提示复审。
- 只修改验收时，其他故事及其批准保持不变。
- aef-story-workspace/v1 持续维护格式和只读 CLI。
- v2 显式导入及“只改一条失败验收”的合成案例。

## 兼容与验证
- 原 StoryCard v1/v2 验证器及许可证保持不变。
- 47 项回归：46 通过，1 项因未提供外部布丁投影路径跳过。
- 22 项新增持续维护测试全部通过。
- 内容门禁、声明式自测、维护前后检查及独立评审通过。
- 以上为结构与回归证据，实际产品效果仍需真实需求试用。

## 注意事项
- CLI 输出候选到 stdout，不自动写项目；保存由宿主按用户授权执行。
- 历史验证使用每个相邻操作的可信基线，不支持跳过中间状态推断批量操作顺序。
- 编号自动建议保证包内唯一，跨包引用使用 package_id/id。
- 安装本版本不会自动迁移旧项目文件，也不会自动更新父包的固定依赖快照。

## 回退
需要回退时可重新选择 v0.2.0 的 Skill；先备份新模式需求包。
v0.2.0 不读取 story-workspace.json，不应将新包当作旧 StoryCard。
