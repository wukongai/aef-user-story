# AEF User Story 用户交付话术

下面的话术用于把 Skill 和用户操作手册交付给其他人。链接公开，不包含布丁后台地址或私有元数据。

## 私聊交付版

```text
这是我做的 AEF User Story Skill，用来把一句模糊需求，通过对话整理成标准 User Story 和可检查的验收条件，再安全写入项目。

Skill 仓库：
https://github.com/wukongai/aef-user-story

中文操作手册：
https://github.com/wukongai/aef-user-story/blob/main/docs/tutorials/aef-user-story-user-manual.zh-CN.md

你不用先学敏捷方法。跟着手册第一步、第二步、第三步做，先用“点击逐字稿跳回视频”的案例跑通，再换成自己的需求就可以。
```

## 极简链接版

## 群公告版

```text
AEF 的第一个独立 Skill：aef-user-story 已经开放。

它不是让 AI 套一句“作为……我希望……”模板，而是带用户完成：需求复述与澄清 → Epic / Story 拆分 → INVEST 检查 → 验收条件 → 两次内容确认 → 写入前批准 → 落地为人读文档和机器合同。

手册按第一步、第二步、第三步展开，每一步都有可直接复制给 Agent 的说法，并提供三个完整案例：
1. 一句模糊需求变成一条 Story；
2. 一堆功能拆成 Epic 和多条 Story；
3. 一条过大的 Story 用 INVEST 重新拆分。

仓库与安装说明：
https://github.com/wukongai/aef-user-story

中文用户操作手册：
https://github.com/wukongai/aef-user-story/blob/main/docs/tutorials/aef-user-story-user-manual.zh-CN.md
```

## 交付时提醒用户

- 第一次建议安装到当前项目。
- 先用手册中的最小案例跑通，再换真实需求。
- User Story、验收条件和写入路径要分别明确确认。
- PRD 是可选项；边界清楚的 Story 可以直接进入 Spec。
