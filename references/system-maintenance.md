# 系统资料保存与恢复

## 保存、版本与四类决定

故事库沿用0.4的独立卡、独立数据、稳定ID和追加历史，不另存一份正文到MVP文档。
系统说明和范围稿使用项目约定路径、文档ID和revision。每次语义改变先保留上版正文及实际审阅记录，再增加修订；只影响有关故事/范围引用。只聊天时给同等可复制恢复摘要。
四类决定分开：
- 内容确认：指定系统结论、Story或AC及其版本。
- 范围确认：指定MVP选中/暂缓集合及理由，不自动确认其中全部内容。
- 写入授权：允许保存哪些文件，不意味着业务批准。
- 开发批准：后续工程阶段的决定，本Skill不签发。
Story和AC的确认仍分别进行。管理记录放过程数据；卡片保持一句原文与编号验收。

当前工具只机器校验故事库及其引用；系统/MVP文档版本、范围语义和批准真实性由宿主对照真实记录审阅。不把它们套入旧产品索引v1宣称通过。

## 恢复与变更

恢复时读：有效定义版本 → 系统/范围最近修订与确认 → 相关故事卡 → 最后一个未决问题。
用户只说“继续”：先用两句话恢复已达成结论和现在要决定的事，再推进该问题，不从定义重来。
若定义或配置责任变化：先列受影响关系、粗能力、MVP与故事；仅受影响项待复审。保留无关卡片和旧版本，不自动批量改写。
没有批准的边界继续标为候选；已经确认的资料可复用，不重复索取同一批准。
